Two retries, same pattern

In both cases the first attempt did most of the engineering and then committed to a wrong model of one detail. The fresh second session traced concrete values instead and solved it quickly.

.tls0x07 lessons

Lessons for next year

What the data and the two failed attempts suggest doing differently. Each lesson ends with one concrete change to adopt.

Restart fresh instead of pushing a stuck session

Both failed attempts ran for many hours through several context compactions. By then the summaries were carrying the wrong hypothesis forward as fact. Both fresh restarts solved the challenge in under an hour, for 0.7% and 3.8% of the cost.

AdoptSet a stop-loss, for example 2 h or $50 with no new verified fact. When it trips, write a handoff note that lists verified facts separately from open hypotheses, and start a new session from that note.

crux A1 $483 → A2 $3.26 · NeonOutRun A1 $110 → A2 $4.17

Build the smallest valid input before theorising

crux A2 made a certificate for the prime 3 and watched the checker accept it. That one concrete run showed the input grammar and the target prime. A1 had spent a day reasoning about the format in the abstract.

AdoptFor any checker or crackme, get one known-good input through the real code early, then trace actual argument and return values. Where an input feeds a hash or key, make sure it is in canonical form.

crux · ch4 image-mapping harness · ch7 unicorn on the real XTEA blob

Treat the prompt text as a spec and expect decoys

FLARE-On 13 was full of decoys. There was the victory-screen string (ch9), FLAG{NICE_TRY} and a rickroll (ch7), managed IL that hid the native hooks (ch6), and cpuminer code around the real routine (ch4). The ch9 note said outright that the victory screen was a dummy.

AdoptBefore submitting, check the candidate against every line of the prompt. Treat a flag that is shown on screen or sitting in plaintext as suspect until the real check is understood.

ch9 A1 decoy rejected · ch7 easter eggs · ch6 decoy IL

Prove it before calling something impossible

NeonOutRun A1 decided the gate was an unsatisfiable mirage because it assumed one operand did not depend on the input. crux A1 decided the missing bytes were free and began a brute-force search. Both conclusions rested on one unchecked assumption.

AdoptBefore labelling a check "unsatisfiable" or starting a brute force of 2³² or more, write out what each operand depends on. Then get a second opinion from a subagent told to argue against the claim.

ch9 sin((K ± t)°) gate · ch8 SHA-256 preimage hunt

Use outside signals as a sanity check

The user pointed out that the top scorer solved crux 10 minutes after FlareCalc. A plan that needs a 3-hour brute force, or a day of work, is probably on the wrong path.

AdoptCheck scoreboard solve gaps at the start. If the plan needs far more effort than the leaders' pace suggests, look for the shortcut first.

Assume the flag can be recovered offline

In ch6 the user had to say twice that no live server existed and the pcap was enough. Every flag this year came from the shipped files alone.

AdoptPut "no live infrastructure; everything needed is in the archive" in the kickoff prompt. When a pcap is included, treat it as the ground truth to decrypt.

ch5 · ch6 · ch7 all solved from the shipped files

Start every challenge with a structured prompt

The early kickoffs were casual ("challenge 4 is in downloads too"). Both successful retries began with one structured prompt: role, archive path, tool location, work directory and the full challenge text. The ch9 retry also named a methodology (recon → find the check → cheapest solve → verify).

AdoptSave a reusable /goal template that covers role, paths, the full prompt, the offline assumption, the detonation policy, the stop-loss, and a "verify before submit" step.

ch8 A2 and ch9 A2 kickoffs, section 06

Have the tooling ready before the event

A lot of the run went into building tools on the spot. That included Ghidra headless scripts, a PE image-mapping harness, Frida redirect hooks, a flat Go-WASM decompiler (wabt output hit 1.8 GB), and a WSLg setup for a Linux ELF.

AdoptPre-build and test a kit: Ghidra batch decompile, unicorn and PE-mapping harness templates, Frida file/socket redirection, WASM instrumentation, a WSL/gdb/gcore profile, and the Defender-safe in-memory extraction step.

section 08 techniques

Pick the model per phase and watch cache cost

Every attempt that ran entirely on Opus 5.5 (ch1–3, crux A2, NeonOutRun A2) solved its challenge for under $11. The long Opus 4.8 sessions (ch5–7, crux A1) account for about 86% of the spend, mostly cache reads from very large contexts. Nineteen subagents in crux A1 did not get it out of the wrong model.

AdoptDefault to Opus 5.5 with short sessions. Give subagents narrow checks with a clear yes or no answer ("is operand X independent of the input?") rather than open-ended re-analysis.

.pdata0x08 methods

Techniques that recurred

ch2 · 3 · 4 · 5 · 7 · 9

Ghidra headless

Batch decompilation through small DecompAll / DecompOne scripts, then grep over the C output.

ch3 · 4 · 7 · 9

Emulate the sample's own code

Unicorn ran a 16-bit COM stage, an XTEA blob and obfuscated V8 helpers. A PE image-mapping harness called ToxicMiner's modified SHA directly.

ch2 · 3 · 5 · 7

RC4 variants and bespoke codecs

Standard, i += 19 step, and reused-keystream RC4. There was also a custom canonical Huffman, a PKWARE Reduce decoder and a de-interleaving packer.

ch5 · 6

Frida as an oracle

Redirected connect and CreateFileW so catthief compressed known inputs, which exposed its Huffman format.

ch6 · 9

Hooked runtimes

A modified CoreCLR detoured managed methods, and Rust hooks rewired V8 builtins. In both, the visible IL or JS was a decoy layer.

ch4 · 7

Brute force in C

A 2³² volume-serial sweep for ToxicMiner, and a 2³² de-interleave seed sweep with a "disassembles cleanly" oracle for FlareCalc.

ch8

WASM binary rewriting

wabt output grew to 1.8 GB, so the run used a custom flat Go-WASM decompiler and spliced entry/exit hooks through a hijacked import.

ch9

Heap dumping under WSLg

gcore on the running Tauri game, then grep the V8 heap for the decrypted 4 KB game script.
